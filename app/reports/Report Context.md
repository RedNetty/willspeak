# Report Context

Goal: test an offline, speech-only assistive system on public TORGO audio, then show that a fine-tuned model can run on a Raspberry Pi 5. This semester measures recognition, fine-tuning, data needs and device performance. It doesn't show that the device works for the intended user.

This map follows Project_Proposal.pdf, mainly §§3–6. Commands and generated-output paths are relative to `app/`, and notes links are relative to this file. Start here, then open the note for the question you care about.

## Naming and Format

New note folders use `<proposal code>-<subject>-<what changed>` in lowercase: `f2-m02-bottom8-all`, `f3-m02-5min`, `p-b-end-to-end`. The fifteen lab tests set up on 2 Oct use `lab-NN-<subject>`, since each extends several proposal items. Pipeline diagnostics use `setup-…`, and proposal pitfalls get a descriptive `…-check`. The note title spells out the same thing. Keep speaker labels like M02 in the text.

The [notes template](../../docs/measurements.md#notesmd-template) defines the sections. Write the prediction before running, then record the exact command, machine, manifest, split, sample sizes, decoder, result and conclusion. If a prediction misses, that's a result to keep, and the prediction stays as written.

## Git Policy

- Track this map, proposal-named experiment notes, code, guides, and the selected public T-1 `results.json` and `provenance.json` files already in Git.
- Ignore generated HTML, hypotheses, unselected JSON output, logs, recordings, datasets, model weights, caches, environments, and transfer bundles. Their existing local files stay in place.
- Private/client reports are excluded by default. The note exceptions are limited to the semester's public experiments and setup checks; do not put private transcripts or identifying data in them.
- Git ignore rules prevent future additions; they do not remove content from older commits. Stage the cleanup for review, then commit under the repository owner's name.
